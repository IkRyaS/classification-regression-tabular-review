## 1. Кросс-валидация

**Кросс-валидация** - способ оценить, насколько хорошо модель будет работать
на **новых** данных, многократно обучая её на одной части выборки и проверяя
на другой.

Если оценивать модель на тех же данных, на которых она обучалась, оценка будет
**завышенной** - модель уже «видела» ответы. Поэтому качество всегда меряют
на данных, которые не участвовали в обучении. Простейший вариант - одна
отложенная выборка (hold-out), более надёжный - кросс-валидация, где каждая
часть данных по очереди становится проверочной.

### 1.1. Hold-Out (отложенная выборка)

Данные один раз делятся на **Train** и **Test**. Быстро, но оценка зависит
от того, какие строки случайно попали в тест.

**Когда использовать.** Когда данных **много** и нужно **быстро**
оценить модель. В курсовой hold-out используется для **финальной** оценки
(тест 20% / 2017 год), а не для сравнения моделей.

### 1.2. K-Fold Cross-Validation

Данные делятся на **K равных частей** (фолдов). Одна используется для проверки,
остальные - для обучения. Процесс повторяется **K раз**: каждый фолд
один раз побывает проверочным. Итог - среднее и стандартное отклонение
K оценок.

### 1.3. Stratified K-Fold Cross-Validation

То же, что K-Fold, но в каждом фолде сохраняется **пропорция классов**.
Используется при **несбалансированных классах**.

**Пример.** 80% примеров - класс A, 20% - класс B. Каждый фолд содержит
те же 80/20.

**Зачем в курсовой.** В credit 78.2/21.8, в churn 73.5/26.5. Без
стратификации доля класса 1 «гуляет» от фолда к фолду, и разброс метрики
растёт из-за случайности разбиения, а не из-за модели.

### 1.4. Leave-P-Out Cross-Validation

В каждой итерации P объектов идут в проверку, остальные - в обучение,
перебираются **все** комбинации.

**Когда использовать.** На очень малых датасетах. **Дорого** - число
комбинаций растёт как биномиальный коэффициент C(n, P).

### 1.5. Time Series Cross-Validation

Для временных рядов: обучение всегда на **прошлом**, проверка - на **будущем**.
Train-окно расширяется от фолда к фолду (`TimeSeriesSplit`).

**Зачем в курсовой.** Demand - временной ряд. Обычный KFold даст
**утечку по времени**: модель учится на 2017 году и проверяется на 2015.

**Деталь реализации.** В demand на одну дату приходится много строк
(по одной на пару магазин-товар). Поэтому `TimeSeriesSplit` применяется
к **уникальным датам**, а не к строкам - иначе один день разрезается между
train и validation.

## 2. Train / Validation / Test

**Аналогия.**

- **Train (обучающая выборка)** - задачи с разбором из учебника.
  Модель «подгоняет» свои внутренние веса.
- **Validation (валидационная выборка)** - домашняя работа. Решаешь сам,
  сверяешь с ответами, меняешь подход (в ML - подбор гиперпараметров и выбор модели).
- **Test (тестовая выборка)** - экзамен. Билеты видишь впервые, подогнать
  решение нельзя.

**Главная ошибка новичков.** Обучить модель, настроить параметры,
проверить на тех же данных и сказать: «У меня точность 99%!». Модель
**запомнила** данные - это **переобучение (overfitting)**. На новых данных
качество окажется заметно ниже.

**Правило.** Тестовую выборку отрезаем **в самом начале** и не трогаем
до финала - ни для обучения, ни для выбора модели.

**В курсовой.** Validation - это кросс-валидация **внутри train**
(отдельная validation-выборка не нужна). Схема:

| Датасет | Test | Валидация на train |
|---|---|---|
| credit, churn | 20%, стратифицированно | `StratifiedKFold(5)` (сравнение), `StratifiedKFold(3)` (подбор) |
| demand | весь 2017 год | `TimeSeriesSplit(5)` по датам (сравнение), `TimeSeriesSplit(3)` (подбор) |

**Признак переобучения в коде** - большой разрыв между метрикой на train-фолдах
(`return_train_score=True`) и на валидации.

## 3. Параметры и гиперпараметры

- **Параметры** - модель находит их сама при обучении.
  Пример: веса в линейной регрессии, пороги в узлах дерева.
- **Гиперпараметры** - настройки, которые задаются **до** обучения.
  Пример: максимальная глубина дерева, `learning_rate`, `C` у SVM.

**Подбор гиперпараметров** - поиск комбинации настроек, при которой
метрика на валидации наилучшая.

- **GridSearchCV** - перебор всех комбинаций сетки. Точно, но дорого.
- **RandomizedSearchCV** - `n_iter` случайных комбинаций из распределений.
  Обычно находит почти то же самое в разы быстрее.

**В курсовой.** `RandomizedSearchCV`: `n_iter = 20` (15 для demand)
для большинства моделей, меньше - для моделей с одним гиперпараметром
и для самых медленных (SVM - 8, SVR - 6). Внутренняя CV - 3 фолда.

**Важно.** `best_score_` - максимум из многих попыток, поэтому он
**оптимистичен**. Честная оценка подобранной модели - только на тесте.

## 4. Метрики классификации

Матрица ошибок: TP (верно нашли класс 1), FP (ложная тревога),
FN (пропустили класс 1), TN (верно отвергли).

### 4.1. Precision, Recall, F1-Score

**Проблема.** В банке 99% клиентов лояльны, 1% уходит. Модель, которая всем
говорит «вы останетесь», имеет Accuracy 99%, но **бесполезна**.

- **Precision (точность)** = TP / (TP + FP) - доля верных среди тех,
  кого модель назвала «уходящими».
- **Recall (полнота)** = TP / (TP + FN) - какую долю реальных «уходящих»
  модель нашла.
- **F1** = 2 · Precision · Recall / (Precision + Recall) - гармоническое
  среднее. Высокое, только если **обе** величины высокие.

**Зависит от порога.** F1 считается по меткам 0/1, которые получаются
из вероятности по порогу (в курсовой - 0.5, порог не подбирался).
Поэтому F1 может сильно отличаться у моделей с одинаковым ROC-AUC.

### 4.2. ROC-AUC

**ROC-кривая** - зависимость TPR (= Recall) от FPR = FP / (FP + TN)
при всех возможных порогах. **AUC** - площадь под ней.

**Интерпретация.** Вероятность того, что случайно выбранному объекту
класса 1 модель даст оценку **выше**, чем случайно выбранному объекту
класса 0. Оценивает способность **ранжировать**.

**Шкала:** 1.0 - идеально; 0.5 - случайное угадывание; < 0.5 - хуже случайного.

**Почему основная в курсовой.** Не зависит от порога и от доли классов
в выборке. Оговорка: при **сильном** дисбалансе (1:100 и сильнее) ROC-AUC
может выглядеть оптимистично, тогда смотрят ещё PR-AUC. У нас дисбаланс
умеренный (≈ 1:3.5), ROC-AUC подходит.

**Для SVM** вероятности не нужны: ROC-AUC считается по `decision_function`,
ранжирование то же самое.

## 5. Метрики регрессии

Задача - прогноз спроса в штуках товара.

### 5.1. MAE (Mean Absolute Error)

MAE = (1/n) · Σ |yᵢ − ŷᵢ|.

**Пример.** Ошиблись на 5 штук сегодня и на 3 завтра: MAE = (5 + 3) / 2 = 4.
«Ошибаемся в среднем на 4 штуки».

**Свойство.** Менее чувствительна к выбросам, чем RMSE.

### 5.2. RMSE (Root Mean Squared Error)

RMSE = √((1/n) · Σ (yᵢ − ŷᵢ)²).

Ошибки возводятся в квадрат, поэтому RMSE **сильнее штрафует** крупные промахи.
Полезна, когда один большой промах для бизнеса хуже многих мелких.

**Свойство.** RMSE ≥ MAE всегда. Для нормально распределённых ошибок
RMSE / MAE ≈ 1.25; если отношение заметно больше - в ошибках есть крупные выбросы.

### 5.3. MAPE (Mean Absolute Percentage Error)

MAPE = (1/n) · Σ |yᵢ − ŷᵢ| / |yᵢ|.

Ошибка в процентах от реального значения. MAE в 5 штук для хлеба
(тысячи штук) - отлично, для икры (3 банки) - катастрофа; MAPE это различает.

**Проблема.** При `y = 0` - деление на ноль. В demand есть одна строка
с `sales = 0`, поэтому MAPE считается **по строкам с `sales > 0`**.
Ещё одна особенность: MAPE сильнее штрафует ошибки на **маленьких** продажах.

## 6. Статистическая значимость

Сравниваем k моделей на N **блоках** (датасетах или фолдах).

### 6.1. Тест Фридмана (Friedman test)

**Непараметрический аналог** дисперсионного анализа с повторными измерениями.

1. Внутри каждого блока модели ранжируются: лучшая получает ранг 1.
2. Считаются средние ранги моделей R̄ⱼ.
3. Статистика: χ²_F = 12N / (k(k+1)) · [Σ R̄ⱼ² − k(k+1)² / 4],
   при H0 распределена примерно как χ² с k − 1 степенями свободы.

**H0:** все модели эквивалентны, их средние ранги равны.

- p < 0.05 -> отвергаем H0: хотя бы одна модель отличается;
- p ≥ 0.05 -> отвергнуть H0 нельзя (это **не** доказательство равенства).

**Поправка Iman-Davenport** (рекомендована Демшаром): F = (N−1)χ²_F / (N(k−1) − χ²_F),
распределение F с (k−1) и (k−1)(N−1) степенями свободы. Менее консервативна.

**Почему не попарные t-тесты.** При 9 моделях - 36 пар. Если каждую проверять
на уровне 0.05, вероятность хотя бы одной ложной «значимости» намного больше 5%
(проблема **множественных сравнений**). Фридман + Неменьи контролируют её.

**Допущение.** Блоки независимы. Фолды одной кросс-валидации **не** независимы
(train-части пересекаются), поэтому p-value на фолдах - ориентир «внутри
эксперимента». Классический вариант Демшара - блок = датасет; но при N = 3
у теста почти нет мощности.

### 6.2. Пост-хок тест Неменьи (Nemenyi test)

Фридман говорит «различия есть», но не говорит, **между кем**.
Неменьи сравнивает модели попарно через **критическую разницу (CD)**:

CD = q_α · √(k(k+1) / (6N)),

где q_α - критическое значение распределения размаха Стьюдента, делённое на √2
(для α = 0.05: k = 8 -> 3.031, k = 9 -> 3.102, k = 10 -> 3.164).

**Правило.** Если разность средних рангов двух моделей больше CD,
они различаются значимо.

**Пример.** k = 9 моделей, N = 2 датасета: CD = 3.102 · √(90/12) ≈ 8.5,
а максимально возможная разница рангов = 8. Значит, на 2 датасетах
**ни одна пара не может различаться значимо**. Поэтому в курсовой блоки - фолды.

### 6.3. CD-диаграмма (Critical Difference diagram)

Модели на оси по среднему рангу. Модели, соединённые горизонтальной линией,
**значимо не различаются**. Показывает группы неразличимых моделей.

## 7. Заполнение пропусков и неправильных значений

### 7.1. Условное и безусловное заполнение

**Безусловное (unconditional).** Одно значение на всю колонку: медиана,
среднее, мода. **Опасно для неоднородных данных.**

**Пример.** Ребёнок 2 месяца, пропущен вес. Если в выборке и дети,
и взрослые, средний вес около 40 кг - **признак испорчен**.

**Условное (conditional).** Статистика **внутри группы** похожих объектов.
Ребёнку 2 месяцев подставится ~5 кг (медиана группы «0-1 год»).

**Группу выбирают по данным.** Условное заполнение имеет смысл, только если
медианы в группах действительно различаются. В credit медиана стажа во всех
возрастных группах = 4 года, т.е. группировка по возрасту ничего не даёт;
по типу жилья и доходу медианы различаются (3-5 лет).

### 7.2. Неправильные значения

Невозможное значение - это тоже пропуск: настоящего значения мы не знаем.
Поэтому его превращают в `NaN` по **логическому правилу** и заполняют так же,
как пропуск. Удалять строки не нужно.

### 7.3. Что применяем в курсовой

| Датасет | Колонка | Правило / метод | Почему |
|---|---|---|---|
| credit | `person_age` > 100 | -> `NaN` -> медиана внутри `cb_person_cred_hist_length` | корреляция возраста и длины кредитной истории ≈ 0.86 |
| credit | `person_emp_length` > возраст − 14 | -> `NaN` | стаж 123 года у 21-летнего |
| credit | `person_emp_length` | медиана внутри `person_home_ownership` × квинтиль дохода + флаг пропуска | по возрасту медианы одинаковые; пропуск информативен |
| credit | `loan_int_rate` | медиана внутри `loan_grade` + флаг пропуска | ставка определяется грейдом (A ≈ 7.5%, G ≈ 20%) |
| credit | полные дубликаты | удаляем | одна строка могла попасть и в train, и в test |
| churn | `TotalCharges` (пробел) | `tenure × MonthlyCharges` = 0 | у всех 11 строк `tenure = 0` - новые клиенты |
| demand | - | пропусков нет, сетка полная | - |

**Где считаются медианы.** Только на train (внутри `Pipeline`, см. раздел 8).

### 7.4. Другие методы

- **Model-based imputation** (`IterativeImputer`, `KNNImputer`) -
  пропуск предсказывается моделью по остальным признакам. Точнее,
  но дороже и сложнее объяснить.
- **Missing as category** - `NaN` становится категорией `'missing'`.
- **Informative missingness** - сам факт пропуска может быть сигналом:
  бинарный флаг `was_missing`. В credit у клиентов без указанного стажа
  доля дефолтов выше средней - поэтому флаг используется.
- **Интерполяция** - для временных рядов, `df['sales'].interpolate()`.

## 8. Утечка данных и Pipeline

**Утечка данных (data leakage)** - в обучение попадает информация, которой
в реальном применении у модели не будет. Оценка получается завышенной.

Типичные источники:

- статистики (медианы, среднее для `StandardScaler`, категории OneHot)
  посчитаны по **всей** таблице, включая тест;
- тест использовался для выбора модели или гиперпараметров;
- во временном ряду модель видит будущее (обычный KFold, лаги через границу групп);
- одинаковые строки в train и test (дубликаты).

**`Pipeline`** - цепочка «заполнение -> кодирование -> модель». В кросс-валидации
весь пайплайн обучается заново на каждом train-фолде, поэтому статистики
никогда не «видят» валидацию.

**`ColumnTransformer`** - разные преобразования для разных колонок
(числовые -> `StandardScaler`, категориальные -> `OneHotEncoder`).

**Свой трансформер** (`ConditionalMedianImputer` в 02_credit) - класс с методами
`fit` (считает медианы групп) и `transform` (подставляет их). Наследуется
от `BaseEstimator, TransformerMixin`, поэтому работает в `Pipeline`.

**Фиксированные правила** (невозможное значение -> `NaN`, формула для `TotalCharges`)
ничего не «учат» по данным, их можно применять до разбиения.

## 9. Кодирование и масштабирование признаков

- **OneHotEncoder** - категория с m значениями -> m бинарных колонок.
  Подходит при малой кардинальности (2-10 значений). `handle_unknown='ignore'` -
  новая категория в тесте даёт нули, а не ошибку.
- **StandardScaler** - (x − среднее) / std. Нужен моделям, чувствительным
  к масштабу: LogReg с регуляризацией, SVM, kNN. Деревьям не нужен, но не мешает.
- **Ordered target statistics (CatBoost)** - категория заменяется средним таргета
  по этой категории, посчитанным **только по объектам, идущим раньше**
  в случайной перестановке. Так нет утечки таргета. Включается параметром
  `cat_features` - тогда OneHot не нужен.

## 10. Временные ряды: лаги и наивный прогноз

- **Лаг** - значение таргета k шагов назад: `sales_lag_1` - вчера,
  `sales_lag_7` - неделю назад. Считается внутри группы
  `groupby(['store', 'item']).shift(k)`, иначе на границе групп «вчера»
  окажется продажей другого товара.
- **Горизонт прогноза.** С `sales_lag_1` модель прогнозирует **на 1 день вперёд**.
  Для прогноза на 90 дней (как в исходном соревновании Kaggle) лаг 1 недоступен.
- **Наивный прогноз** - «завтра = сегодня» (`lag_1`); **сезонный наивный** -
  «как неделю назад» (`lag_7`). Обязательная точка отсчёта: модель, которая
  их не бьёт, бесполезна.
- **Календарные признаки** - день недели, месяц, год, день месяца
  (сезонность и тренд).

## 11. Модели: краткий справочник

| Семейство | Модель | Идея | Ключевые гиперпараметры |
|---|---|---|---|
| Линейные | **LogReg** | σ(w·x + b) - вероятность класса 1; по умолчанию L2-регуляризация | `C` = 1/λ |
| Линейные | **LinearReg / Ridge / Lasso** | y = w·x + b; Ridge - штраф λ‖w‖², Lasso - λ‖w‖₁ (зануляет веса) | `alpha` |
| Деревья | **DecisionTree** | рекурсивное разбиение по порогам признаков | `max_depth`, `min_samples_leaf` |
| Бэггинг | **RandomForest** | много глубоких деревьев на бутстрэп-выборках со случайным подмножеством признаков, усреднение -> меньше дисперсия | `n_estimators`, `max_features` |
| Бустинг | **XGBoost** | деревья строятся последовательно, каждое исправляет ошибки (градиент) предыдущих; регуляризация в функции потерь | `learning_rate`, `max_depth`, `n_estimators` |
| Бустинг | **LightGBM** | то же, но гистограммы признаков и рост дерева «по листьям» (leaf-wise) - быстро на больших данных | `num_leaves`, `learning_rate` |
| Бустинг | **CatBoost** | симметричные (oblivious) деревья, ordered boosting, нативные категории | `depth`, `l2_leaf_reg` |
| Метрические | **kNN** | ответ - голосование / среднее k ближайших соседей | `n_neighbors`, `weights` |
| Margin | **SVM / SVR** | разделяющая гиперплоскость с максимальным зазором; ядро rbf - нелинейная граница. SVR - «трубка» ширины ε вокруг прогноза | `C`, `gamma`, `epsilon` |
| Вероятностные | **Naive Bayes (Gaussian)** | теорема Байеса + допущение независимости признаков, каждый признак ~ нормальный внутри класса | `var_smoothing` |

**Bias-variance.** Одно глубокое дерево - низкое смещение, высокая дисперсия
(переобучается). Бэггинг уменьшает дисперсию, бустинг - смещение.

**Почему нейросети на табличных данных часто проигрывают бустингу**
(Grinsztajn et al., 2022):

- таблицы неоднородны: признаки разных типов и масштабов, много нерелевантных;
- целевая функция часто **кусочная** (резкие пороги), а нейросети тяготеют
  к гладким функциям;
- нейросети не инвариантны к поворотам пространства признаков, а в таблице
  каждая колонка имеет свой смысл;
- табличные датасеты обычно небольшие (тысячи - сотни тысяч строк);
- бустинг из коробки устойчив к выбросам и масштабу и требует меньше подбора.

## 13. Доп. задание 1: сильный дисбаланс классов

**Сильный дисбаланс** - доля минорного класса ≤ 5-10% (в Give Me Some Credit - 6.7%, соотношение 1 : 14).

### 13.1. Метрики

- **Accuracy** при дисбалансе бесполезна: константа «всегда 0» даёт 93.3%.
- **PR-AUC (average precision)** - площадь под кривой Precision-Recall. Уровень случайной модели = доле класса 1
  (0.067), а не 0.5 как у ROC-AUC. Чувствительна именно к качеству в зоне класса 1.
- **Balanced Accuracy** = (Recall₀ + Recall₁) / 2.
- **MCC (коэффициент корреляции Мэтьюса)** = (TP·TN − FP·FN) / √((TP+FP)(TP+FN)(TN+FP)(TN+FN)), от −1 до 1;
  учитывает все 4 клетки матрицы ошибок, 0 у константы.
- **Cost-sensitive метрика** - средняя стоимость ошибок: (C_FN·FN + C_FP·FP) / n. В работе C_FN = 10, C_FP = 1.

### 13.2. Порог

Классификатор выдаёт вероятность; метку даёт порог t. Порог 0.5 оптимален только для Accuracy при откалиброванных
вероятностях. **Байесовский порог** для стоимостей: t* = C_FP / (C_FP + C_FN) (при C_FN = 10, C_FP = 1 - 0.091).
Порог подбирают на out-of-fold предсказаниях train (не на тесте!): под max F1, под заданный Recall или минимум стоимости.

### 13.3. Работа с классами

- **class_weight='balanced'** - вес класса = n / (2·n_класса); ошибка на редком классе дороже.
- **scale_pos_weight = n₀/n₁** (XGBoost, LightGBM), **is_unbalance=True** (LightGBM) - то же для бустинга.
- **sample_weight** - вес каждого объекта, например по бизнес-стоимости ошибки.
- **Oversampling:** **SMOTE** - синтетические объекты на отрезках между соседями класса 1;
  **ADASYN** - больше синтетики там, где класс 1 трудно отделить; **SMOTEENN** - SMOTE + очистка
  Edited Nearest Neighbours. **Undersampling** - случайно выбросить часть класса 0.
- **Ловушки:** ресемплинг до разбиения (синтетические копии тестовых объектов попадают в train - утечка);
  SMOTE на категориальных и дискретных признаках (появляются «1.6 иждивенца»). Правильно - `imblearn.Pipeline`,
  сэмплер работает только при `fit` на train-фолде.
- Перевзвешивание и ресемплинг **сдвигают вероятности** вверх -> в основном эквивалентны сдвигу порога.

### 13.4. Калибровка

Вероятности **откалиброваны**, если среди объектов с прогнозом 0.2 действительно 20% класса 1.

- **Reliability diagram** - средний прогноз vs реальная доля по корзинам прогноза.
- **Brier score** = mean((p − y)²); **log loss** = −mean(y·log p + (1−y)·log(1−p)).
- **Platt scaling** - логистическая регрессия поверх оценок модели; **Isotonic regression** - монотонная
  кусочно-постоянная функция (гибче, нужно больше данных). В sklearn - `CalibratedClassifierCV`.

### 13.5. Двухстадийный подход

Стадия 1 - дешёвый фильтр с высокой полнотой отсекает очевидный класс 0; стадия 2 - модель на оставшемся
подмножестве, где дисбаланс мягче.

## 14. Доп. задание 2: скошенный таргет

**Скошенный таргет** - большинство значений малы (часто нули), но редкие «гиганты» дают большую долю суммы.
В freMTPL2: 96.3% полисов без выплат, верхний 1% выплат - 38% всей суммы.

### 14.1. Диагностика

- **Skewness** (асимметрия) = E[(y−μ)³]/σ³; **kurtosis** (эксцесс) = E[(y−μ)⁴]/σ⁴ − 3 (тяжесть хвостов).
- **Гетероскедастичность** - дисперсия ошибки зависит от признаков / уровня прогноза.
  **Breusch-Pagan**: регрессия квадратов остатков на признаки (H₀ - дисперсия постоянна). Вариант Коэнкера
  (робастный) не требует нормальности ошибок. **White**: то же с квадратами и произведениями признаков.
- **QQ-plot** - квантили остатков против квантилей нормального распределения.
- **Cook's distance** - насколько меняются все прогнозы при удалении объекта; «влиятельный» при D > 4/n.

### 14.2. Метрики

- **WAPE** = Σ|e| / Σy - MAE в долях от суммы; не ломается на нулях.
- **sMAPE** = mean(2|e| / (|y| + |ŷ|)); при y = 0 и ŷ > 0 равна 200%.
- **Pinball loss** (квантильная потеря) для уровня α: α·(y − ŷ) при y ≥ ŷ, (1 − α)·(ŷ − y) иначе.
  Оптимум - α-квантиль. При α = 0.5 - половина MAE.
- **Девиация Tweedie / Poisson / Gamma** - мера качества для распределений из семейства Tweedie.
- **Нормированный Gini** - качество ранжирования рисков (используется в страховании).
- **Σŷ / Σy** - совпадает ли сумма прогнозов с суммой фактических значений (калибровка портфеля).
- **Важно:** оптимум MSE - условное среднее, MAE - условная медиана. При 96% нулей медиана = 0, поэтому по MAE
  «лучшая» модель - константа 0, бесполезная для бизнеса.

### 14.3. Преобразования таргета

- **log1p:** обучаемся на log(1 + y), прогноз - exp(f) − 1. Это оценка **медианы**, а не среднего -> систематическое
  занижение. **Smearing-поправка Дуана (1983):** ŷ = exp(f(x))·mean(exp(eᵢ)) − 1, eᵢ - остатки на train
  (в задании названа «поправкой Смолински»).
- **Box-Cox** - степенное преобразование, только для y > 0. **Yeo-Johnson** - обобщение на y ≤ 0.
- **Винзоризация** - обрезка таргета по квантилю (например, 99.9%), квантиль считается на train.
- **Ловушка:** считать метрику на преобразованной шкале. Метрика всегда - на исходной (евро, штуки).

### 14.4. Функции потерь

- **Huber** - квадратичная при |e| ≤ δ, линейная дальше (устойчива к выбросам).
- **Quantile (pinball)** - прогноз α-квантиля.
- **Poisson, Gamma, Tweedie** - потери из обобщённых линейных моделей (лог-связь, прогноз > 0).
  Tweedie с 1 < p < 2 - сложное Пуассон-Гамма распределение: масса в нуле + непрерывный хвост.
- **Асимметричная потеря** - разные штрафы за недо- и переоценку (в работе - квадратичная, недооценка × 5).

### 14.5. Двухстадийная модель (hurdle / частота × тяжесть)

E[y] = P(y > 0) · E[y | y > 0]: классификатор «будет ли выплата» × регрессор (часто Gamma) суммы на ненулевых.

### 14.6. Прерывистый спрос

**Croston** - раздельное экспоненциальное сглаживание размера ненулевого спроса и интервала между ними;
**SBA** - поправка смещения Syntetos-Boylan; **TSB** - сглаживание вероятности спроса вместо интервала.
Применимы, если ADI (средний интервал между ненулевыми значениями) > 1.32.
